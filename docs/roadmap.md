# 拡張の計画

ランの外（拠点・保管庫・クラフト・装備の組み立て）を受け止める土台を先に作り、その上にアタッチメント → センサー → スキル → 敵の順で載せる。

| 段階 | 中身 | 先に決めること（`design.md` の「決めること」） |
|---|---|---|
| 1. 土台 | ステータス修正の積み上げ、画面の流れ（拠点 → 出撃 → 結果）、保存、データの分割 | なし |
| 2. 持ち込みと持ち帰り | 保管庫、装備の組み立て、クラフト、アタッチメント、5種の武器、防具・カバン | 死んだときの扱い、アタッチメントの箇所数、クラフトの段数 |
| 3. センサーと情報 | 設置型モジュール、無線の設置数、強化 | 開始時に見えるもの、強化の項目、使うときのコスト |
| 4. ビルド | スキル・パッシブ（ユニークのセット＋一般枠）、アルティメット、ラン中のバフ、パートナー | セットの数と手に入れ方、枠の数 |
| 5. 敵 | 敵の能力表、人間が使うドローン・ロボット、エリアの難易度 | 敵の強さの調整を何に結び付けるか |
| 6. 世界 | キャンプと拠点の移動、マップの追加、物語 | キャンプでできること、物語の見せ方 |

## 段階ごとの作り
### 1. 土台
- 武器・防具・プレイヤーの性能は、基礎値に修正（加算・乗算）を積み上げて計算する。アタッチメント・スキル・バフはすべてこの修正として書く
- 画面は「拠点」「ラン」「結果」を切り替える。拠点のメニューは Preact、ラン中の HUD は DOM を直接書き換える
- 保管庫・素材・装備・組み立ては IndexedDB に保存し、JSON で書き出し・読み込みできる

### 2. 持ち込みと持ち帰り
- 武器は種類ごとに1つ。アタッチメントの組み合わせで傾向を変える
- 武器ごとに弾薬が1種類ある（5種類）
- どの組み合わせでも理論 TTK が1.5秒を下回らないことを `npm run ttk` で全組み合わせ確認する

### 3. センサーと情報
見える情報の出どころを「範囲・出せる段階・壁を越えるか」を持った一覧にし、視線・ビーコン・設置モジュール・スキルを同じ形で扱う。

### 5. 敵
敵の強さの調整項目を「敵の能力表」に分け、エリアや装備で差し替える。`npm run smoke` で、決まった動きのボットとの1対1・1対3の勝率を出して効き目を測る。

### 3〜5 で共通
設置物（センサー・タレット）、投げ物、ドローン、パートナーは、人とは別の種類としてマップ上に置く。
