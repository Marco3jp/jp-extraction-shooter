# マップの大改修の計画

マップを広げ、どの脱出地点からでも出られるようにし、脱出した場所の近くにキャンプを置いて次のランをそこから始められるようにする。広くなったぶん、移動手段を足す。マップは区・市・県の単位まで後から足していける作りにし、遠くの区画を読み込んだり捨てたりしても、プレイヤーにロードを感じさせない。

## 遊び方の変化

- マップは地続きの広い1枚。1回のランで回るのはその一部で、ランの長さは今と同じ7分前後
- ランはキャンプ（最初は決まった出発地点）から始まる
- 脱出地点はマップの各地に常に複数あり、どこから出てもよい
- 脱出すると、その脱出地点の近くにキャンプを置ける。次のランはそこから始まる
- 脱出地点の近くでしかキャンプを置けないので、置けない場所が出る。今は受け入れ、後で考える
- 東京から大阪のような遠い移動は、地続きのマップの上では歩かせない。新幹線や飛行機のカットインを見せている間に、行き先の地方を読み込む

## 1. 脱出地点とキャンプ（済）

今の秋葉原のマップで作った。数値は仮。

- 脱出地点で E を押すと迎えを呼べる。20秒で迎えが来て、来てから中に2秒いれば脱出。呼ぶと 60m 以内の敵が呼んだ人を狙って寄ってくる
- 脱出した後の拠点の画面で、脱出地点から 150m 以内の歩ける所をクリックしてキャンプを置く。キャンプは1か所で、死んでも残る。出撃準備の画面でたためる
- 変換で閉じた空き地を埋めてあるので、空いているマスはどれもつながっている。キャンプをどこに置いても、マップのどこへでも行ける

残っていること：

- 変換のとき、地区ごとに1〜2か所、開けた場所（公園・駅前・大きな交差点）を脱出地点にする。今は `tools/maps/*.json` の `layout.extracts` に手で書いた5か所

## 2. 縮め方

マップ全体を同じ倍率で縮める（案は 0.7 倍）。どの地点も、自分の実際の緯度・経度だけでゲームの座標が決まる。範囲を後から足しても、作り済みの場所は1マスも動かない。

- ゲームの座標の原点は、関東全体で1か所に固定する。マップごとの原点は持たない
- 道は実際の幅ではなく、道の種類ごとに決めたゲーム用の幅で描く。縮めても細い道が通れなくなるのを防ぐ
- 似た街並みを切り詰める今の縮め方（`tools/osm_to_map.py` の `plan_cuts` と `shrink`）はやめる。帯をマップの端から端まで抜くので、範囲を足すたびにマップ全体の座標が決め直しになるため
- 遠さは移動手段（「4. 移動手段」）で埋める
- 単調な住宅街だけを短くしたくなったら、県全体で一度だけ決めた「縮める強さの地図」に沿って滑らかに縮める。今は作らない

今のキャンプはマップ名とマップの中の座標で保存しているので、新しい座標に移るときに、緯度・経度を経由して写す。

## 3. 区画の読み込み

### 区画
- マップを 128m 四方の区画に分け、区画ごとに1つのファイルにする。中身は地面・塞がっている所・建物・遮蔽物・路面の表示・標識・町名・脱出地点
- ファイルは圧縮し、ブラウザの `DecompressionStream` で展開する
- 区画の一覧と、全体マップ用の縮小した絵（拡大の段階ごとのタイル）を別のファイルに置く

### 距離ごとにやること
画面に映るのは 70m × 60m ほどなので、かなり遠くで出し入れする。

| やること | プレイヤーからの距離 |
|---|---|
| 読み込む | 640m 以内 |
| 当たり判定と敵を動かす | 384m 以内 |
| 描く | 256m 以内 |
| 捨てる | 900m より遠く |

読み込む距離と捨てる距離に差をつけて、境目を行き来しても出し入れを繰り返さないようにする。

### 重さを散らす
- ファイルの取得・展開・形の組み立ては Web Worker でする。メインスレッドは出来上がったものを置くだけ
- 1フレームで置く区画の数に上限を付ける。置く順は、近い順と進む向きを合わせて決める
- 進む先を「今の速さ × 8秒」ぶん先読みする。乗り物が速いほど遠くまで読む
- メッシュとテクスチャは捨てずに次の区画へ使い回す。マップの広さに関係なく、メモリと GC の量が一定になる
- 行き先が先に分かる移動（長距離移動レール・長距離移動アイテム・キャンプからの出撃）は、使っている間やロード画面の間に行き先を読み終える
- 読み込みが間に合わなかった区画は、地面と当たり判定を先に出し、建物の部品は後から足す

### ゲームの計算
- 当たり判定の格子は 1024m 四方を、端と端がつながった形で持つ。プレイヤーが動いたら、外れた所を新しい区画で上書きする。セルを引くのはビット演算だけで済む
- 経路探索は、読み込んである範囲の中だけで探す
- 敵と箱は、ランの seed と区画の番号から決める。区画を読んだとき、同じランなら同じ中身が出る
- 倒した敵や開けた箱は、捨てた区画のぶんも小さく覚えておき、戻ってきたら再現する
- 敵と箱の数は 100m 四方あたりの数で決める。勢力の縄張りは地区ごとに割り当てる

### 描画
- 地面のテクスチャは区画ごとに描く（1m を4ピクセルで 512 × 512）
- 建物は区画ごとにまとめる
- ミニマップ・全体マップは、1m を1ピクセルで描いた 512m 四方の絵のうち、写す範囲にかかるものだけを読む。全体マップを県の単位で見るときは、もっと縮めた段階の絵を足す

## 4. 移動手段

| 手段 | 動き | 置き方・手に入れ方 |
|---|---|---|
| ダッシュパッド | 踏むと道の向きに 30m ほど飛ぶように進む。途中で撃てる | 変換のとき、長い直線の道（60m 以上）に置く |
| 自転車 | 乗ると移動速度が2倍。乗っている間は撃てない。降りるのに 0.3 秒。撃たれると降りる | 持ち込む装備（靴と別の枠）。拠点でクラフトする |
| スキル・アイテム | 長距離移動レール（アルティメット）、長距離移動アイテム | `docs/plans/skills.md` と `docs/plans/items.md` |
| 新幹線・飛行機 | 地方から地方へ移る。カットインを見せている間に行き先を読み込む | 地方を2つ以上作ってから決める |

敵も自転車に乗るかは、敵の強さの調整を決めるときに決める。

## 5. 範囲

`tools/osm-raw/kanto-261031.osm.pbf` から切り出す。秋葉原駅の西の電気街へ広げ、その次に神田を通って東京駅まで南へ広げる。座標は pbf の駅と町名の点から取った。

| 段階 | 緯度 | 経度 | 縮める前の広さ | 入る所 |
|---|---|---|---|---|
| 今 | 35.6970〜35.7015 | 139.7736〜139.7800 | 約 580m × 500m | 昭和通り口・佐久間町・台東1丁目 |
| 電気街 | 35.6960〜35.7050 | 139.7670〜139.7800 | 約 1.2km × 1.0km | 外神田1〜6丁目、末広町駅、中央通り |
| 東京駅まで | 35.6770〜35.7050 | 139.7630〜139.7800 | 約 1.5km × 3.1km | 神田駅、大手町、日本橋、東京駅 |

その先は、移動手段がひととおりできてから区の単位で一度に広げ、さらに市や県の単位まで広げる。

- 変換は区画ごとに別々にできるようにする。範囲を足したときは、その範囲の区画だけ作り直す。区画の境目の建物や道は、隣の区画のぶんも少し読んでから切る
- 容量の見当：23区を 0.7 倍で区画にすると約1.9万区画。今の秋葉原では1区画 4〜7KB だったので、10KB と見て約 190MB。電気街を変換したら測り直す
- GitHub Pages はサイト全体で 1GB までなので、県の単位まで行くと置き場所を別に考える

## 作る順番

脱出地点とキャンプは済んでいる。ここから先は、スキル → アイテム → パートナーの後に作る。

1. 今の秋葉原のマップを区画に切り、区画の読み込みを作る。区画のファイル・格子・区画ごとの描画は済み。ミニマップと全体マップも済み。距離に応じた出し入れ・Web Worker・区画ごとの敵と箱が残っている
2. 新しい縮め方を変換に入れ、電気街を変換する
3. ダッシュパッドと自転車
4. 東京駅まで広げる
5. 変換のときに脱出地点を自動で置く

`npm run smoke` に、区画を読み込みながら長い距離を走らせたときの1ティックの処理時間を足す。描画側の1フレームの重さは、ブラウザで長い距離を走って確かめる。

## 決めること

- 縮める倍率（案は 0.7 倍）と、道の種類ごとのゲーム用の幅
- 脱出の待ち時間（試作は呼んでから20秒）と、呼んだ音が届く距離（試作は 60m）
- キャンプを置ける距離（試作は 150m）と、1か所にするか複数持って出撃のときに選ぶか
- キャンプでできること（今はランの出発地点になるだけ。`docs/design.md` の「キャンプでできること」）
- 自転車を入れるか、ダッシュパッドだけにするか
- 県の単位まで広げたときのファイルの置き場所
