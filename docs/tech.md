# 技術の方針

## 動かし方
- ブラウザで開けば遊べる。ビルド結果は静的ファイルだけなので、GitHub Pages に置いている（`.github/workflows/deploy.yml`）。手元では `npm run dev` で開く
- GitHub Pages はリポジトリ名の下に置かれるので、ビルドのときに `BASE_PATH` で置き場所を渡す
- 対象は PC のブラウザ（Chrome / Edge / Firefox）とマウス＋キーボード
- スマホは後で対応する。画面は横長を基準にする

## 使うもの
- TypeScript + Vite
- 描画は Three.js。3D で作り、カメラを斜め上に固定する
  - 3D にしておけば、建物の2階や高低差を後から足せる。手前の壁を透かす処理も書ける
- 物理エンジンは入れない。移動と当たり判定は、平面上の円と 1m のマス目で自前で書く

## 構成
ゲームの計算と描画を分ける。

- ゲームの計算は 30Hz の固定ティックで回す。Three.js にも DOM にも依存させない
- 描画はゲームの計算の状態を読んで、ティックの間を補間して描く
- 別のエンジンに移すときは、描画と入力だけ書き直せば済むようにしておく

### 情報の見え方
敵ごとに、毎ティック「どこまで見えるか」を1つの段階で決め、描画はその段階で見た目を変える。

| 段階 | 見えるもの |
|---|---|
| 0 | 何も出さない |
| 1 | 影 |
| 2 | 影＋敵の型（近距離・中距離・遠距離） |
| 3 | 影＋型＋体力 |

段階は、自分の視線が通るか、ビーコンやセンサーモジュールの範囲に入っているかで決め、一番高いものを採る。センサーの強化は、範囲と出せる段階の数値を上げるだけにする。

### マップ
`tools/osm_to_map.py` が、OpenStreetMap の建物・道路・緑地・鉄道をゲーム用の 1m グリッドに変換する。

マップごとの設定（範囲・名前・出発地点）は `tools/maps/<名前>.json` に書く。出発地点は緯度・経度で書き、変換がゲームの座標にして `index.json` の `layout` に入れる。脱出地点は変換が選んで同じ `layout` に入れる。

ゲームの座標は、関東全体で1か所の原点（北緯37度・東経138.4度）から、実際の長さを 0.8 倍した m で測る（`SCALE` `ORIGIN_LAT` `ORIGIN_LON`）。経度1度の長さは北緯35.7度で決める。マップごとの原点は持たないので、範囲を足しても作り済みの場所の座標は変わらない。変換は範囲を区画の境目まで広げた四角の上で行い、範囲の外のマスは「マップの外」（地面 `Ground.outside`、塞がっている）にする。

0. 範囲内の `building` `highway` `landuse` `leisure` `railway` `amenity` `shop` の way と、お店・施設・地名・駅の点を取り出して `tools/osm-raw/` に置く。取り出し方は2つあり、出力の形は同じ
   - `npm run extract-map -- tools/maps/<名前>.json tools/osm-raw/<地方>.osm.pbf`：Geofabrik の地方ごとのファイル（`<地方>-latest.osm.pbf`）から osmium-tool で切り出す。ふだんはこちらを使う。multipolygon の relation も、外側の輪を way として出す
   - `npm run fetch-map -- tools/maps/<名前>.json`：Overpass API から取得する。relation は取らない
1. 取得したものを描き込む。細い歩道や階段は描かない
2. ならす：1〜2m の隙間と、建物と歩道の間の幅4m以下の空き地は建物で埋める。建物の輪郭は3×3の多数決でならす。小さな地面のかけらは周りに合わせる
3. 範囲の外を落とす：範囲をまたぐ道や建物は外まで描かれているので、範囲の外のマスを「マップの外」にする
4. 車・自販機・バリケードを置く。車は細い道の路肩に置く
   - 置いた後に、一番広い空き地とつながっていない空き地を、隣の建物を広げて埋める。建物に囲まれて入れない場所を目的地にすると、経路探索が毎回失敗して重くなる。400㎡ より広いものを埋めたら、変換が場所を出して知らせる
5. 建物の種類を決める。中にあるお店・施設の点、建物の種類と名前、面積・階数・周りの土地の使われ方の順に見て、最初に決まったものを採る。道に面した側（`front`）も出す
6. 横断歩道・中央線・停止線・マンホール・通りの名前の標識・駅名標・町名の範囲を出す
7. 固定レールとダッシュパッドを置く（`tools/travel.py`）。道の線を way の境目でつないでから、線からのずれが 1.5m 以内の直線に分け、塞がったマスに当たらない区間だけを使う
   - 幅 9m 以上の道には固定レールを置く。上り下りが別の way の道は、間隔 26m 以内で向きがそろっていれば、長いほうを2本の真ん中へずらして1本にする。レールどうしが交わる所で切り、240m より長いものは等分し、50m より短いものは捨てる
   - 幅 9m 未満の道（service を除く）には、60m 以上の直線にダッシュパッドを 40m おきに置く。両向きに 30m 飛んでも直線の中に降りる所だけに置く
8. 脱出地点を置く（`tools/extracts.py`）。駅名標の位置、150㎡ 以上の緑地の真ん中、幅 11m 以上の道が2本以上交わる点を候補にし、それぞれ 16m 以内で一番開けたマスへ寄せる。開け具合は周り 17m 四方の空いているマスの割合で、7割に満たない候補は捨てる
   - 開け具合に、駅前は 0.2、公園は 0.1 を足した点の高い順に選ぶ。先に町ごとに1か所ずつ、次に2か所目を足す。脱出地点どうしは 180m、出発地点からは 120m 離す
   - 固定レールの端から 10m、ダッシュパッドから 6m 以内には置かない。脱出地点の上で E を押すと迎えを呼ぶほうが先に決まり、レールに乗れなくなるので

`npm run map -- tools/maps/<名前>.json` で 1〜8 を通して `public/maps/<名前>/` に書き出す。128m 四方の区画ごとの `<i>_<j>.json.gz`、一覧の `index.json`（範囲・出発地点などの `layout`・町名・区画と絵の番号）、全体マップ用の絵 `overview/<i>_<j>.png`（512m 四方を 1m 1ピクセルで描いたもの）の3種類。

- 地方のファイルと取り出した結果（`tools/osm-raw/`）はリポジトリに入れていない。Overpass API が混んでいると 429 / 504 が返るので、取得スクリプトは別のサーバーも順に試す
- 秋葉原の範囲では、2つの取り出し方で way は全部一致した。点の差は、地方のファイルを作った時刻より後の編集だけだった
- 建物の種類の判定は `tools/buildings.py` にある。種類の名前はゲーム側の `src/data/buildings.ts` と揃える
- 町名は、地名の点（`place=quarter` `neighbourhood` `suburb`）の位置を中心にして、一番近い中心の町名にする。「外神田三丁目」のような丁目は「外神田」にまとめる。マップの外150mより遠い町は入れない
- 遊びに関わる格子（地面・塞がっている所・遮蔽物）は 1〜4 だけで決まる。5〜7 を変えても格子は変わらない
- 全体マップの絵には、固定レールとその端、ダッシュパッドも描く。ミニマップも同じ絵を使う
- 建物・遮蔽物・標識・固定レール・ダッシュパッドは、左上の角や位置（レールは始点）がある区画にまるごと入れる。隣の区画にはみ出してもよい。地面に描く表示は、両側の地面に描けるよう、区画の外 8m までのものも入れる
- 区画のファイルは gzip した JSON。Vite の開発サーバーは `Content-Encoding: gzip` を付けて返し、ブラウザが先に展開するので、`src/chunkworker.ts` は先頭の2バイトを見てから `DecompressionStream` に通す

`GameMap` は、読み込んだ区画を 2048m 四方の、端と端がつながった格子に書き込む。持っている区画は、捨てる距離（900m）の2倍と先読みの分まで広がるので、それより広くしている。マスは座標の下位11ビットで引き、読み込んでいないマスは塞がっている扱いにする。マスの中身は `blocked` `solidAt` `groundAt` `buildingAt` で読み、遮蔽物のスキルは `setSolid` で書く。経路探索は出発点を真ん中にした 1024m 四方の中だけを探す。

ミニマップ・全体マップ・キャンプを置く画面は、`overview/` の絵のうち写す範囲にかかるものだけを読んで描く（`MapView.drawArea`）。

区画の出し入れは `ChunkStreamer`（`src/stream.ts`）が毎フレーム決める。

| やること | プレイヤーからの距離 |
|---|---|
| 読む | 640m 以内。今の速さで8秒進んだ先からも 640m 以内 |
| `GameMap` に置く | 届いた区画を近い順に1フレーム2個まで |
| 描く | 256m 以内。1フレーム2個まで作る。出撃の直後は全部作る |
| 描くのをやめる | 320m より遠く |
| 捨てる | 900m より遠く（先読みの点からも） |

- ファイルの取得・展開・JSON の読み取り・格子のデコードは Web Worker（`src/chunkworker.ts`）でする。メッシュとテクスチャはメインスレッドで作る
- 出撃の前に、出発地点から 640m 以内の区画を読み終えるまで待つ（`ChunkStreamer.loadAround`）
- 描画は区画ごとに、地面の板（1m を4ピクセルで 512 × 512 のテクスチャ）・建物と遮蔽物のメッシュ・標識・「止まれ」をまとめる（`Renderer.syncChunks`）。地面の板とテクスチャは片付けても捨てず、次の区画に描き直して使う。建物のメッシュは区画ごとに作って捨てる
- 地面は道の縁を隣の区画のマスで決めるので、隣の区画が届いたら描き直す
- 箱と落ちている物は、プレイヤーから 90m 四方の中だけを描く。中身が変わったときと、前に描いた所から 24m 動いたときに描き直す。マップ全体の箱は描ける数（400個）より多い

地図データを含めて公開しているので、OpenStreetMap のクレジット（ODbL）をゲーム画面と README に書いている。

### 敵の状態の伝え方
リロード開始・巻き開始・シールド割れ・武器の持ち替えを、ゲームの計算からイベントとして出す。描画と効果音はイベントを受けて鳴らす。

### 弾
弾除けができるように、弾は一瞬で当たる判定にせず、飛んでいく物体として扱う。描画は弾・箱・炎などをまとめて描く（InstancedMesh）。

### 投げ物とダッシュ
`src/sim/throwables.ts` が投げ物を扱う。着地点と炎の範囲は、投げる前の予告表示と同じ関数（`throwLanding` `thermiteLine`）で出す。ダッシュは数ティックのあいだ移動速度を上書きする。

テルミットの炎に触れると、炎の中にいる間と出てから0.6秒は移動速度が35%になる（`Actor.burnT`）。ダッシュには効かない。

### 固定レール・ダッシュパッド・自転車
数値は `src/data/travel.ts` と `src/data/gear.ts`（`BIKES`）、ラン中の処理は `src/sim/travel.ts` と `src/sim/skills.ts`（レール）。設計は `docs/plans/map.md` の「移動手段」。

- 固定レールは、アルティメットのレールと同じ `World.rails` に `owner: null` で入れる。乗っている間の動きも同じ `rideStep` で、速さだけ `FIXED_RAIL.speed` にする。`nearRail` は、固定レールなら端から `FIXED_RAIL.board` 以内のものを探し、いくつもあればカーソルの向きに一番近いものを選ぶ
- 固定レールとダッシュパッドは、敵と箱と同じく `syncSpawns` で区画と一緒に置いて外す。番号は `World.nextFixed` で負の数を振る。`nextId` を使うと、人の番号が地図の設備の数でずれ、パートナーの撃ち合いの動き（番号で揺らしている）が変わる
- ダッシュパッドは、ダッシュと同じく `dashT` `dashDir` `dashSpeed` を書き換えて飛ばす
- 自転車は `Actor.bike` に乗り降りの状態を持つ。撃たれたら `applyDamage` から `startDismount` を呼ぶ。パートナーの `bike` は、プレイヤーが乗っていて自分がついて歩いている（`follow` か `return`）間だけ乗っている状態にする
- 敵は固定レール・ダッシュパッド・自転車を使わない

### 敵の動き
状態遷移で書く（巡回・交戦・引いて巻く・詰める）。足りなくなったら Behavior Tree に替える。

- 0.2秒ごとに、見えている敵対勢力のうち一番近い相手を狙う。プレイヤーも敵どうしも同じ扱い
- 銃声が聞こえる距離にいる敵は、撃った相手を狙って寄ってくる
- 単独の敵と、グループの半分は、ときどき巡回の中心を60〜140m先へ移す。縄張りの外で出会わせるため
- 投げ物を避ける動きは、状態と関係なく移動を上書きする（`grenadeEscape` `fireEscape`）
  - グレネードには、着地から「反応時間＋0.25秒」で気づき、爆発の届かない所か爆心から隠れられる所へ走る
  - 炎の中に入ったら、炎の左右と両端の先のうち、狙っている相手から見えない所を優先して出る。相手が瀕死（シールド込みで50以下）で自分に110以上残っていれば留まる

- 巡回の行き先まで探索の上限（12000マス）で道が見つからなければ、今いる所を巡回の中心にする。同じ行き先を4秒ごとに探し直し続けると重いため
- プレイヤーから 384m より遠い敵は止めておく（`ENEMY_ACTIVE_RANGE`）。区画を読む距離（640m）より短いので、動き出す前に周りの区画は読めている

### 敵と箱の置き方
`src/sim/spawn.ts` が、区画を `GameMap` に置いたときにその区画の敵と箱を置き、区画を捨てたときに外す。ゲームの計算の `step` の始めに揃える（`syncSpawns`）。

- 中身はランの seed と区画の番号から決める。同じランなら、区画を読み直しても同じ所に同じものが出る
- 数は、区画の歩けるマスの数に比例させる（1万マスあたりグループ 1.0・単独 0.9・箱の置き場 7.1・地面の物 26。数値は仮）。端数は乱数で切り上げる。区画の縁の1マスには置かない
- グループの勢力は、グループの真ん中がある町の勢力にする。町の勢力は町名のハッシュだけで決まるので、ランが変わっても同じ。組み合わせはその勢力の `ENEMY_SPAWNS` から選ぶ
- グループは真ん中がある区画のもの。区画を捨てるときは、メンバーがどこにいてもまとめて外す
- 捨てた区画で倒した敵、中身が変わった箱、拾われた物は `World.memory` に覚えておき、読み直したときに再現する。生きている敵は元の場所に戻る
- 出発地点から近い所（グループの真ん中は 80m、単独は 60m、箱は 10m）には置かない

経路探索は、平面のうちはグリッド＋A*。燃えている炎の所は1歩の重みを13倍にして、回り道を選ばせる。炎が着いたら全員が経路を引き直す。高低差を入れたら navmesh に替える。空いているマスはどれもつながっているので、目的地・出発地点・脱出地点・敵・箱・キャンプは、塞がっていないマスならどこでも選べる。

### スキル・パッシブ・バフ
定義は `src/data/skills.ts` `src/data/buffs.ts`、ラン中の処理は `src/sim/skills.ts` `src/sim/buffs.ts`。

- 数値を変えるだけのもの（加速・速射・弾の威力・ダッシュ2回・キルでシールド回復・強化パーツ）は、`Actor.mods` に修正を足す。`until` が null なら外すまで続く。足し外しのたびに `refreshStats` が、アタッチメントの修正と合わせて武器の性能・移動速度・シールドの上限・ダッシュの回数・スキルとダッシュのクールダウンの倍率を計算し直す
- 強化パーツは `source` を `buff:<id>` にして足す。同じ `source` は1つまでなので、同じ種類は重ならない
- 武器以外の項目（`ActorStat`）も、武器と同じ積み上げ方をする
- 理論 TTK の下限はアタッチメントまでの性能に掛け、スキルとバフはその後に掛ける。効いている間は下限を下回る
- 倒したときの効果は、`applyDamage` の死亡の処理から `onKill` を呼ぶ
- 遮蔽物は `map.solid` のマスを一時的に `Solid.cover` にする。弾・視線・経路探索・当たり判定は、ほかの遮蔽物と同じに扱う。立てたとき・消えたときに敵全員が経路を引き直す。マップはランをまたいで使い回すので、`createWorld` の始めに `resetSolid` で元に戻す
- 敵はスキルを使わない

### パートナー
動きは `src/sim/partner.ts`、数値は `src/data/partners.ts`。設計は `docs/plans/partners.md`。

- `Actor.team` が `"partner"` の人として置く。勢力はプレイヤーと同じなので、弾は当たらない
- 敵と同じ `Ai` を持ち、経路・投げ物の避け方は `ai.ts` の関数を使う。撃ち合いで隠れる所と出て撃つ所は `findPeekCover` で探し、`Actor.partner.cover` に持つ。`step` は `team` を見て `updatePartner` と `updateEnemy` を呼び分ける
- 武器は `Actor.build` から `refreshStats` で作る。`ActorBuild.minTtk` で敵と同じ下限を掛け、ダメージと弾速を下げる修正を `Actor.mods` に入れておく
- 倒れたら `alive` を false にするだけで、持ち物は落とさずランも続く。起こすと `alive` を戻す
- プレイヤーが当てた相手を `World.focus` に残し、パートナーが優先して狙う
- `updateInfo` は、パートナーの視線が通る敵もプレイヤーが見ているのと同じ段階にする

### データ
数値は `src/data/` に種類ごとの型付き定数で書く（`constants` `items` `weapons` `attachments` `gear` `heals` `enemies` `recipes` `throwables` `buildings` `skills` `buffs` `partners` `travel`）。`src/sim/data.ts` はそれをまとめて読み込むだけ。

### 武器の性能
武器の性能は、素の値（`src/data/weapons.ts`）にアタッチメントの修正を積み上げて `src/sim/stats.ts` の `computeWeapon` で計算する。同じ項目の修正は、加算を全部足してから (1 + 割合の合計) を掛ける。理論 TTK が下限を下回る組み合わせは、連射速度を下げて下限に揃える。下限はプレイヤーが0.75秒、敵が1.5秒（`PLAYER_MIN_TTK` `ENEMY_MIN_TTK`）。プレイヤーが理論値で倒すには全弾命中などの条件がそろう必要があるので、低めにしている。強すぎたら1.5・1.25・1.0秒と段階的に下げる形にする。敵の武器も同じ仕組みで作り、弾速だけ半分にして避けられるようにする。

### ランの外
- `src/meta/profile.ts`：保管庫・素材・武器・アタッチメントの付け方・持ち込む装備とスキル。クラフトとランの結果の反映もここ
- `src/meta/save.ts`：IndexedDB への保存と、JSON の書き出し・読み込み。保存先の名前は改名前の `sensor-extraction` のまま。変えると、それまでのセーブが読めなくなる
- `src/ui/hub/`：拠点の画面（Preact）。ラン中の HUD は `src/hud.ts` で DOM を直接書き換える
- 町名の「〜エリア」は、最後に撃った・撃たれてから6秒たつまで出すのを待つ

### 確認用のスクリプト
- `npm run ttk`：武器ごとに、アタッチメントの全組み合わせの理論 TTK と、そこへスキル・パッシブを全部掛けたときの最短を出す。アタッチメントまでで下限を下回る組み合わせ（敵の武器は敵の下限で見る）があれば失敗で終わる。デプロイの前にも走る
- `npm run smoke`：ゲームの計算を画面なしで回し、例外が出ないか、漁れる物の量、1ティックの処理時間、敵どうしで3分間に何人倒れるか、武器ごとの1対1の勝ち数、投げ物のダメージとダッシュの距離、テルミットの減速、敵が投げ物を避けたときのダメージと炎の回り込み、箱が接している建物の用途、スキルごとの効き目（受けたダメージ・2秒で進んだ距離・1対1で倒すまでの時間・壁で弾が止まるか・巻き検知の円のずれ・広域探知の段階・弾倉なしの弾の減り方）、強化パーツが1ランに出る数と拾ったときの効き目・受け渡し、パートナー（歩いて付いてくる距離・パートナー0〜2体と敵の3人組の撃ち合い・パートナーと敵の中距離型の1対1・倒れたパートナーを起こす時間）、移動の設備と自転車（固定レールの本数とつながり・1本に乗ったときの速さと撃てるか・乗り継いで行ける距離とカーソルの向きで選べるか・ダッシュパッドで飛ぶ距離と横切ったときに飛ばないか・自転車の乗り降りの時間と速さと撃てないこと・自転車と固定レールでパートナーがどれだけ離れるか・離れすぎたパートナーを後ろへ移すか）、区画を読み直したときの敵と箱（倒した敵・開けた箱・拾った物が戻らないか）、区画の出し入れ（本来の距離と縮めた距離の2通りで、マップを 12m/s で往復し、読んだ・捨てた回数、置き場所の取り合いの回数、周りの区画が間に合わなかった回数、1ティックの処理時間）を出す。1対1のボットは動かないので、射程の短いショットガンは測れない。項目は CPU の数だけ並べて回し、1ティックの処理時間を測る項目だけは先に1つずつ回す。`npm run smoke -- 自転車 パートナー` のように名前の一部を渡すと、その項目だけ回す

## 遊んで確かめること
1. 斜め見下ろしで、遮蔽に隠れて巻く・撃ち合う・リロード中に詰める、が気持ちよく感じられるか
2. 情報の見え方の段階（N / B キーで切り替え）で、遊び方が変わるか
3. 実際の PC で 60fps を保てるか（ヘッドレスのソフトウェア描画でしか確かめていない）
4. 0.8 倍に縮めた地図での、敵と箱の密度と、移動の長さ
5. ショットガンの強さ
6. 建物の部品で、何の建物か見分けられるか。カメラが南から見るので、正面が北を向いた建物は部品が見えない
7. テルミットで、遮蔽から出るか焼かれ続けるかを迷う場面が生まれるか
8. 固定レール・ダッシュパッド・自転車で、行きたい所へ行くのが楽になるか。レールの上で撃たれやすすぎないか。ダッシュパッドが細い道を歩くときの邪魔にならないか
