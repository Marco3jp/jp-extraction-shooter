# 技術の方針

## 動かし方
- ブラウザで開けば遊べる。ビルド結果は静的ファイルだけなので、GitHub Pages に置いている（`.github/workflows/deploy.yml`）。手元では `npm run dev` で開く
- GitHub Pages はリポジトリ名の下に置かれるので、ビルドのときに `BASE_PATH` で置き場所を渡す
- 対象は PC のブラウザ（Chrome / Edge / Firefox）とマウス＋キーボード
- スマホは後で対応する。画面は横長を基準にする

## 使うもの
- TypeScript + Vite
- 描画は Three.js。3D で作り、カメラを斜め上に固定する
  - 3D にしておけば、建物の2階や高低差を後から足せる。手前の壁を透かす処理も書ける
- 物理エンジンは入れない。移動と当たり判定は、平面上の円と 1m のマス目で自前で書く

## 構成
ゲームの計算と描画を分ける。

- ゲームの計算は 30Hz の固定ティックで回す。Three.js にも DOM にも依存させない
- 描画はゲームの計算の状態を読んで、ティックの間を補間して描く
- 別のエンジンに移すときは、描画と入力だけ書き直せば済むようにしておく

### 情報の見え方
敵ごとに、毎ティック「どこまで見えるか」を1つの段階で決め、描画はその段階で見た目を変える。

| 段階 | 見えるもの |
|---|---|
| 0 | 何も出さない |
| 1 | 影 |
| 2 | 影＋敵の型（近距離・中距離・遠距離） |
| 3 | 影＋型＋体力 |

段階は、自分の視線が通るか、ビーコンやセンサーモジュールの範囲に入っているかで決め、一番高いものを採る。センサーの強化は、範囲と出せる段階の数値を上げるだけにする。

### マップ
`tools/osm_to_map.py` が、OpenStreetMap の建物・道路・緑地・鉄道をゲーム用の 1m グリッドに変換する。

1. 範囲（緯度経度の矩形）を指定して Overpass API から取得したものを描き込む。細い歩道や階段は描かない。取得には、範囲内の `building` `highway` `landuse` `leisure` `railway` の way を `out geom tags` で出すクエリを使い、結果を `tools/osm-raw/area.json` に置く
2. ならす：1〜2m の隙間と、建物と歩道の間の幅4m以下の空き地は建物で埋める。建物の輪郭は3×3の多数決でならす。小さな地面のかけらは周りに合わせる
3. 縮める：縦横に近い大通り・高架の鉄道、4000㎡以上の建物、1000㎡以上の駅と公園を「残す場所」にして、その行・列は切らない。それ以外では、同じ向きの細い道が3本以上並ぶと内側を1本おきに抜き、36m を超える街区は 28m に詰める
4. 車・自販機・バリケードを置く。車は細い道の路肩に置く

地図データを含めて公開しているので、OpenStreetMap のクレジット（ODbL）をゲーム画面と README に書いている。

### 敵の状態の伝え方
リロード開始・巻き開始・シールド割れ・武器の持ち替えを、ゲームの計算からイベントとして出す。描画と効果音はイベントを受けて鳴らす。

### 弾
弾除けができるように、弾は一瞬で当たる判定にせず、飛んでいく物体として扱う。描画は弾・箱・炎などをまとめて描く（InstancedMesh）。

### 投げ物とダッシュ
`src/sim/throwables.ts` が投げ物を扱う。着地点と炎の範囲は、投げる前の予告表示と同じ関数（`throwLanding` `thermiteLine`）で出す。ダッシュは数ティックのあいだ移動速度を上書きする。

### 敵の動き
状態遷移で書く（巡回・交戦・引いて巻く・詰める）。足りなくなったら Behavior Tree に替える。

- 0.2秒ごとに、見えている敵対勢力のうち一番近い相手を狙う。プレイヤーも敵どうしも同じ扱い
- 銃声が聞こえる距離にいる敵は、撃った相手を狙って寄ってくる
- 単独の敵と、グループの半分は、ときどき巡回の中心を60〜140m先へ移す。縄張りの外で出会わせるため

経路探索は、平面のうちはグリッド＋A*。高低差を入れたら navmesh に替える。目的地は、プレイヤーの出発地点から歩いて行けるセルからだけ選ぶ。建物に囲まれて入れない場所を目的地にすると、探索が毎回失敗して重くなる。

### スキル・パッシブ・バフ
全部「ステータス修正」として同じ仕組みに載せる。

- ステータスへの加算・乗算
- 「被弾したとき」「巻き終わったとき」のようなきっかけで起きる効果

### データ
数値は `src/data/` に種類ごとの型付き定数で書く（`constants` `items` `weapons` `attachments` `gear` `heals` `enemies` `recipes` `throwables`）。`src/sim/data.ts` はそれをまとめて読み込むだけ。

### 武器の性能
武器の性能は、素の値（`src/data/weapons.ts`）にアタッチメントの修正を積み上げて `src/sim/stats.ts` の `computeWeapon` で計算する。同じ項目の修正は、加算を全部足してから (1 + 割合の合計) を掛ける。理論 TTK が下限の1.5秒を下回る組み合わせは、連射速度を下げて1.5秒に揃える。敵の武器も同じ仕組みで作り、弾速だけ半分にして避けられるようにする。

### ランの外
- `src/meta/profile.ts`：保管庫・素材・武器・アタッチメントの付け方・持ち込む装備。クラフトとランの結果の反映もここ
- `src/meta/save.ts`：IndexedDB への保存と、JSON の書き出し・読み込み。保存先の名前は改名前の `sensor-extraction` のまま。変えると、それまでのセーブが読めなくなる
- `src/ui/hub/`：拠点の画面（Preact）。ラン中の HUD は `src/hud.ts` で DOM を直接書き換える
- ランには `makeRunLoadout` で作った持ち込みの内容だけを渡す。ゲームの計算は Profile を見ない

### 確認用のスクリプト
- `npm run ttk`：武器ごとに、アタッチメントの全組み合わせの理論 TTK を出す。下限を下回る組み合わせがあれば失敗で終わる。デプロイの前にも走る
- `npm run smoke`：ゲームの計算を画面なしで回し、例外が出ないか、漁れる物の量、1ティックの処理時間、敵どうしで3分間に何人倒れるか、武器ごとの1対1の勝ち数、投げ物のダメージとダッシュの距離を出す。1対1のボットは動かないので、射程の短いショットガンは測れない


## 試作のファイル
| パス | 中身 |
|---|---|
| `tools/osm_to_map.py` | OpenStreetMap の JSON をゲーム用マップに変換する |
| `src/data/` | 数値の定義 |
| `src/sim/` | ゲームの計算。Three.js にも DOM にも依存しない |
| `src/sim/stats.ts` | アタッチメントを付けた武器の性能の計算 |
| `src/meta/` | 保管庫・クラフト・保存 |
| `src/ui/hub/` | 拠点の画面 |
| `src/ui/icons.ts` | アイテムのアイコン |
| `src/render/renderer.ts` | Three.js での描画 |
| `src/hud.ts` | HUD・持ち物の画面・キルログ |
| `src/mapview.ts` | ミニマップと全体マップ |
| `src/input.ts` `src/audio.ts` | 入力・効果音 |

## 遊んで確かめること
1. 斜め見下ろしで、遮蔽に隠れて巻く・撃ち合う・リロード中に詰める、が気持ちよく感じられるか
2. 情報の見え方の段階（N / B キーで切り替え）で、遊び方が変わるか
3. 実際の PC で 60fps を保てるか（ヘッドレスのソフトウェア描画でしか確かめていない）
4. 切り詰めた地図での、敵と箱の密度
5. ショットガンの強さ
